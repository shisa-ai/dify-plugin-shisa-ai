# Supply Chain Audit — Shisa AI Model Provider for Dify

## Snapshot

- Date: 2026-08-05
- Repository: `shisa-ai/dify-plugin-shisa-ai`
- Branch reviewed: `main` plus `security/supply-chain-baseline`
- Ecosystem: Python 3.12, Dify plugin
- Package authority: `uv.lock`
- Working tree at audit start: clean

## Install and release surfaces

- Development and CI dependencies are resolved by uv from `pyproject.toml` and `uv.lock`.
- CI uses `uv sync --frozen --no-install-project` and checks that the lockfile and exported `requirements.txt` remain unchanged.
- `requirements.txt` is a fully pinned, hashed export used by the Dify plugin package surface.
- Plugin packaging is manual; no automated publishing workflow or long-lived publishing token exists.
- Generated `.difypkg` files are excluded from Git.

## Direct dependencies

- `dify-plugin==0.10.0`
- `httpx==0.28.1`
- Development validation: `pyyaml==6.0.3`

The transitive dependency inventory, versions, artifact URLs, and hashes are recorded in `uv.lock`. A deterministic CycloneDX SBOM is generated by `scripts/generate_sbom.py`.

## Resolution controls

- Routine resolution cutoff: `2026-07-29T00:00:00Z`, seven days before this audit snapshot.
- Future routine lock refreshes must advance the cutoff to a reviewed timestamp at least seven days in the past.
- Emergency security updates may bypass the age gate only when the PR documents the vulnerability and reason.
- Git, URL, editable, local-path, and alternate-index dependencies are not used.
- CI consumes the committed lockfile with frozen installs.

## GitHub Actions review

- Workflow token permission is `contents: read`.
- External fork workflows require maintainer approval.
- Only GitHub-owned actions and the explicitly approved `astral-sh/setup-uv` action are allowed at repository level.
- Every action is pinned to a full commit SHA.
- `pull_request_target` and `workflow_run` are prohibited by `scripts/validate_workflows.py`.
- CI does not access secrets or publish artifacts.
- Dependency changes receive a dependency-review job and remain subject to required human review.

## Repository controls

- `main` requires PR review, current required checks, linear history, and resolved conversations.
- Force pushes and branch deletion are blocked.
- `v*` tags are protected.
- Secret scanning, push protection, Dependabot security updates, and private vulnerability reporting are enabled.

## Exceptions and open remediation

1. The Dify plugin packaging CLI is not currently executed in CI. Before adding release automation, review the CLI dependency, pin it, use a protected release environment, generate and attach the SBOM, and add provenance/attestation.
2. Routine Dependabot PRs require the configured seven-day cooldown and human review; security updates may bypass cooldown under the documented exception process.
3. Release packages must continue to be tested in a non-production Dify workspace before publication.
